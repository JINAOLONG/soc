FILE docs/model_spec.md
1: # System model — P0 definitions with user-approved P1 event order
2: 
3: Virtual time uses milliseconds, data sizes MiB, bandwidth MiB/ms and power W.
4: Service g has arrival a_g >= 0, relative deadline D_g > 0, absolute deadline
5: d_g = a_g + D_g, importance H or L and a finite acyclic task graph. Completion
6: F_g is the last node completion. Nodes inherit service importance. Instance,
7: node and resource IDs are unique stable strings. Reject cycles, empty compatible
8: sets, nonfinite/negative timing inputs and missing predecessor identities.
9: 
10: Resources are CPU0, CPU1, CPU2, CPU3, GPU0, NPU0. Each unit executes at most one
11: node. GPU/NPU internal parallelism is abstracted by execution time. Compatible
12: sets must include CPU-only, GPU-oriented, NPU-oriented, multi-compatible and
13: limited-alternative types; universal compatibility is not an acceptable workload.
14: Every resource-specific node has positive estimated and realized durations.
15: 
16: Execution is non-preemptive: a started node keeps its resource and contiguous
17: execution interval until completion. No migration, replication or replanning of
18: that interval is allowed. Pending nodes may be reordered/remapped.
19: 
20: Communication version 1 has no shared-bus contention. For edge u→v with size b,
21: transfer to destination r can start at u's completion C_u. Same unit: delay 0.
22: Different units: latency(type(u),type(r)) + b / bandwidth(type(u),type(r)); all
23: parameters nonnegative with strictly positive bandwidth. Independent transfers
24: overlap with each other and with compute. Data readiness on r is
25: max over predecessors of C_u + delay(u,r); a root is ready at service arrival.
26: These logical copies are destination-specific and retained after transfer.
27: Remapping a pending node recomputes readiness for the new destination; it cannot
28: reuse a copy at another unit or backdate transfer before predecessor completion.
29: The implementation may calculate copy readiness lazily from immutable completed
30: outputs; this is not a reservation or a started execution. No future predecessor
31: completion is treated as an actual completed output.
32: 
33: States are distinct: dependency_ready (all predecessors completed), data_ready
34: (copies arrived on a specified destination), planned (nonbinding proposal),
35: resource_ready (destination idle), started, running, completed. A proposal may
36: wait or be replaced. Actual start >= arrival, all predecessor completions,
37: destination-specific data readiness and resource availability.
38: 
39: Deterministic event ordering approved by the user in the P1 task (D1): at virtual time t,
40: process all completions, expose all arrivals at t, then refresh the immutable
41: scheduler view and dispatch only feasible starts; repeat zero-time dispatch
42: until no start is chosen. Ties use stable (service_id,node_id,resource_id).
43: No positive-length execution interval overlaps another on the same unit; touching
44: endpoints are legal. When no start is possible, advance to the next true event
45: or feasible data-readiness wakeup. Detect a deadlock rather than silently dropping
46: jobs. After stopping arrivals, drain all admitted work, even after deadline miss.
47: 
48: Scheduler boundary: only arrived public DAGs, estimates, deadlines, H/L, completed
49: outputs, running task start/elapsed observations, idle/busy state and observable
50: data readiness. Never disclose the private event queue, future arrivals, true
51: remaining running durations or future disturbances. Busy-unit release prediction
52: must use estimates and elapsed time, never actual queued completion timestamps.
53: 
54: Execution disturbances must be scheduler-independent deterministic functions of
55: (workload seed, service ID, node ID, resource ID, disturbance version). The
56: generator materializes the same workload artifact for every compared method.
57: No RNG call sequence may depend on scheduler decisions. Exact event, trace and
58: metric reproducibility is required for identical code/config/workload identities.
59: 
60: P1 must independently validate legal traces and reject crafted violations of
61: precedence, data readiness, compatibility, overlaps, duration, unique execution,
62: non-preemption, assignment, completion and full arrival accounting. It must include
63: a 6–8-node hand-checkable DAG, simultaneous events, equality at deadline and drain.
64: Implementation and test evidence are tracked in P1_implementation_spec.md and
65: reports/P1_correctness.json; this model does not itself assert correctness PASS.
