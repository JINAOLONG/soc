## Collection and exact fields

Actual repository URL fixed to JINAOLONG/soc HTTPS. Git object format explicitly sha1 in this proposed family; unknown format rejected pending explicit extension. Context includes actual HEAD40hex, tree40hex, SYMBOLIC branch plus nonnull branch name or DETACHED plus null, frozen source commit separately, source_bundle SHA, exact source-scope manifest SHA, all observed relevant path/rawSHA/gitblob-or-null, relevant dirty/untracked booleans, whole-repository dirty boolean, dirty-scope policy SHA, execution-contract SHA, execution-image manifest SHA and SEALED_READ_ONLY_SOURCE_AND_DEPENDENCIES mode. No field is inferred from policy or a plan. Actual invoking checkout can differ from frozen source commit through a metadata-only commit, but this gets distinct context and run identity; relevant bytes must match the frozen bundle exactly.

Raw observation set is mandatory: actual argv/cwd/host/timestamps/exit/stdout/stderr for git rev-parse --show-toplevel, remote get-url origin, rev-parse HEAD, rev-parse HEAD^{tree}, symbolic-ref --quiet --short HEAD (detached exit1 explicitly supported only if HEAD/tree valid), status --porcelain=v1 --untracked-files=all and source-file/blob hash reads; refs bind exact raw bytes. No secrets or credential dumps. Repository mismatch, failed required observation, malformed OID, missing raw ref or contradictory booleans =>reject. Paths must be safe repo-relative, unique ASCII; relevant rows exactly equal approved source-scope roster in ASCII path order, never omit changed/untracked relevant files. Boolean dirty flags must be derived from captured observations, not manual declarations. Arbitrary output exclusions are prohibited: approved policy separately enumerates allowed CALIBRATION artifacts and metadata paths; relevant source/config/dependency entries cannot be excluded.

For each real GENERATE_MAIN/DERIVE_CONTROL/ENGINE_PRIMARY/ENGINE_REPLAY/TRACE_VALIDATE/METRIC_RECOMPUTE/DIAGNOSTIC_RECOMPUTE/M2_ANALYSIS process: PRE_SPAWN collection after read-only source/dependency sealing and before trusted admission; POST_EXIT collection after actual child termination before acceptance/publication. Both include context digest/ref, subject (known generation/primary/replay/analysis attempt), role, host, collected UTC, raw observation refs and OBSERVED/FAILED status with reason. Pre/post context must match. Changed context or failed postcheck retains all outputs but cannot COMPLETE. Aborted/not-started process may have FAILED or missing post observation, never a fabricated successful receipt.

Pre/post checks alone cannot exclude a source swap restored during execution. Therefore proposed execution image is an immutable content-addressed/read-only source+dependency snapshot, and trusted executor loads only its verified manifest. Workers must not load mutable checkout modules/plugins outside that image. This is an explicit engineering trust/validation requirement, not an existing platform guarantee. Inputs/output roots remain separately controlled; sealing source is not sealing or reading reserved scientific data.

## Hash scope and lifecycle

SEMANTIC_CANON_V2 remains the exact unchanged ASCII/integer/closed-object canonicalizer. All exact context fields enter context preimage digest; no observation timestamp or future run/attempt enters context. Every provenance body field, including phase/time/raw refs/context/subject, enters its own digest. Original body bytes have independent ARTIFACT_REF rawSHA/size/kind; raw object is the BODY only, envelope holds ID/digest/ref outside BODY to avoid self hashing. Raw and semantic hashes have separate validation duties even if bytes happen to be canonical.

Order: approved source/contract → observed sealed execution context → context digest → RUN_PREIMAGE_V3 (context and contract hash required) → run/attempt → PRE_SPAWN provenance → process → POST_EXIT provenance → immutable provenance inventory → completion preimage. Generation has known generation attempt first; its receipt V3 additionally binds observed context/provenance inventory/domain, then resolution/workload. Workload semantic payload/draw KEY unchanged. Context excludes generation/run IDs, future receipts, outputs and own digest. New preimages cannot hash their own envelope or the final commit that will contain a later report.

EXECUTION_PLAN_PREIMAGE_V3 explicitly binds selected observer route,coordination policy,threshold bundle,execution-contract,typed-schema,provenance-policy,M2-contract and coordination-contract hashes. All are known definition choices before root authorization/generation; no actual context or outcomes enter that plan. V2 plan is not an effective V3 plan. Bundle membership and exact document approval must be checked semantically; a string label does not supply missing values.

Inventory explicitly includes generation/control birth provenance, primary/replay and every validator/metric process used for trial acceptance; stage inventories separately include diagnostic and M2 analysis provenance. Kind/subject/role/phase uniqueness required, not merely minItems. Cross-record context/source/host checks and raw Git evidence are mandatory semantic predicates; JSON type validation alone cannot prove truthful observation.

## Complete/reuse and rejection

No V3 run COMPLETE without valid mandatory provenance, matching RUN_PREIMAGE_V3 and all existing physical/metric/replay conditions. No old PROCESS_RESULT/SCIENTIFIC_RUN_RECORD can be relabeled V3. Different actual execution source/context produces different V3 run identity; exact reuse requires original full bytes, actual context and source/contract/plan/input identities, never recomputing a receipt to patch old evidence. A metadata-only HEAD still differs as observed provenance; equality of relevant source does not permit pretending it was the old actual HEAD.

Proposed receipt kinds: EXECUTION_CONTEXT, EXECUTION_PROVENANCE_PRE_SPAWN, EXECUTION_PROVENANCE_POST_EXIT, PROVENANCE_INVENTORY. Ref kind,body namespace/version,raw/semantic hash and linked context all verified. Missing field/ref, wrong HEAD, dirty mismatch, wrong host/subject/role, different pre/post context, unsealed/incorrect image, failed observation, bad path or self-reference fail closed; raw failure retained. No current task HEAD is inserted as a future scientific value.

Future tests NOT_RUN: valid clean contextual record; metadata-only versus relevant-source commit; actual dirty/untracked changes; omitted relevant file; lying boolean; wrong HEAD/tree/repo/branch; wrong context/ref/hash/phase; duplicate phase; missing postcheck; transient mutable import rejected by sealing; source changed during preparation; fake fixture lineage; cross-family reuse; context hash field omission and cycle; failed Git command/unknown process exit; every stage analysis process covered.
