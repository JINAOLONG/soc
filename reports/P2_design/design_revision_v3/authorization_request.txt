## 0. 任务性质与最高优先级约束

你现在负责 SOC 项目的研究设计文档修订、证据追溯和静态对抗性复审。

本任务是一个**独立的文档修订任务**，不是科学设计批准、代码实现授权或实验执行授权。

本轮唯一目标：

1. 重新核验 Git 仓库身份和实际检查点。
2. 阅读原始研究契约、现有 v1/v2 设计及 V3 审查证据。
3. 对 V3-F01–F05 进行范围有限、可追溯的文档修订。
4. 对关键备选方案、逻辑边界、身份依赖和跨文档契约进行静态检查。
5. 生成新的版本化文档包、审查报告、实际命令收据和机器可读状态。
6. 将仍需要人工选择的事项明确保留为 UNAPPROVED。
7. 在文档修订与静态复审完成后停止，等待人工审阅。

**本轮没有科学实现、工作负载生成或运行实验的授权。**

严禁：

- 启动 P2 或任何科学校准入口。
- 生成、物化、运行或重放科学工作负载。
- 执行 B1–B5 调度方法进行科学比较。
- 访问任何非 CALIBRATION 分区的 realization 或 outcome。

- 创建 validation/formal unlock 或任何推进令牌。
- 将历史审计建议、静态 PASS 或报告完整性检查解释为人工批准。
- 覆盖历史报告、重写失败记录、修改旧 v1/v2 文件以消除审计差异。
- 使用 force-push、rebase、reset --hard、clean -fd 或其他可能覆盖用户修改的操作。

若任务与本约束冲突，优先停止并报告，不得自行扩大授权。

## 4. V3-F01：M1R 观察域与阴性判据

这是本轮最高优先级事项。

### 4.1 必须重现并核验的逻辑问题

重新检查以下已报告推导：

1. ADAS 8/16 节点模板的根节点结构。
2. MAIN 首次同刻 H/L 到达时的 ready 集合。
3. 第一次合法正时长派发后的公共状态。
4. 该状态的 running 变化及状态等价去重规则。

6. 当前 `NOT_SUPPORTED` 分支对每个 seed/condition 完整覆盖率的要求。
7. `F=0` 与 `F>0` 两种情况。
8. `SUPPORTED`、`NOT_SUPPORTED`、`INCONCLUSIVE` 的全部必要条件和优先级。

使用现有模板、事件规则和已登记定义进行纯静态推导。

不得读取科学工作负载，不得通过生成随机样本来检验可达性。

### 4.2 至少比较两条逻辑不同的路线

在新文档中分别定义并比较以下路线；它们是分析选项，不是批准的默认方案。

**路线 A：保留原观察域与覆盖契约。**

- 保留原 E/F 定义及现有 FULL 资格。
- 不删除单 ready 状态，不改变去重规则。
- 对完整但覆盖不足的观测，严格区分证据不足与完整阴性。
- 明确在现有 ADAS 结构下，`NOT_SUPPORTED` 是否可能不可达。
- 讨论是否接受“阴性无法成立，因此只能报告 INCONCLUSIVE”的研究结果边界。
- 不得宣称不可达的分支已经得到科学否定证据。

**路线 B：重新定义可判定的观察域或扩展诊断覆盖。**

必须进一步区分两个可能方向，不能混为一谈：

1. 显式扩展 M1R 的诊断能力，使原来无法满足 FULL 条件的公共状态也能产生可审查的诊断结果。
2. 显式收窄主要 estimand 的目标观察域，同时保留全部原始状态、排除状态和覆盖率作为审计证据。

对每种方向说明：

- 哪些状态仍在原始 E 中。
- 哪些状态进入新的分析域。
- F 的资格条件是什么。
- 排除状态如何记录。
- `SUPPORTED`、`NOT_SUPPORTED`、`INCONCLUSIVE` 的确切逻辑。
- 阴性结论能支持的命题及不能支持的命题。
- 是否改变原始研究契约或只改变观察器。
- 固定 suffix 及当前 K 枚举范围造成的剩余盲区。
- 所需人工批准的内容。

不能为了使阴性分支可达而静默删除单 ready 状态、放宽覆盖率或改名隐藏缺失。

### 4.3 固定 suffix 的局限

保留并准确说明已报告的手算反例：

- 当前 K 的 16 种映射全部得到 `g=0`。
- 改动一个后继映射可改善 H 平均预测完成时间 `111/256 ms`。
- 该改善比例大于 `1/20`。
- 这是静态解释反例，不是运行结果，也未证明该状态实际出现在 B2 或校准样本中。

该反例说明：固定 suffix 的 FULL 仅覆盖受限枚举空间；即使完整覆盖，也不能证明更大映射空间中不存在机会。

不得将它描述为新候选算法或科学收益。

### 4.4 覆盖率及阈值

现有未批准提案包括：

- FINE：`tau=1/100`、`frequency=1/100`。
- COARSE：`tau=1/20`、`frequency=1/20`。
- 支持覆盖率：`F/E >= 4/5`。
- 阴性覆盖率：`F/E = 1`。
- 支持稳定性：至少 `8/10` seeds。
- 阴性频率条件：至多 `2/10` seeds。

这些值全部保留为待批准科学假设。

不得根据未执行的结果选择阈值，不得声称这些数字已由原始来源证明充分。

应分别讨论：

- 见证式阳性结论和排除式阴性结论所需证据是否合理不同。
- 覆盖不足是否导致 INCONCLUSIVE。
- 缺失、无效、不完整和完整零改善是否分别处理。
- 对不同场景结构，阴性证据要求是否具有可实现性。
- 观察域的变化是否使原有阈值失去原有含义。

如果没有足够依据确定唯一判据，输出精确的决策表和未解决问题，不得擅自补默认值。
