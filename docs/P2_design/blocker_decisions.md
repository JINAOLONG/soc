# 五个阻断的决定表：全部为 DRAFT

本页的建议均 `PROPOSED_REQUIRES_APPROVAL`。引用 E01–E14 定义在
evidence_and_traceability.md。没有把建议当成已批准科学规则，也没有读取科学结果。

## P2-B1 — 科学工作负载生成：UNRESOLVED

**事实与缺口：**E01–E03 给出三场景、8/16 节点、兼容/通信/可见性/排空约束；
workload_spec.md:10–12 明示具体参数未提供。全部逐字段缺口见 workload_gaps.md。
这些字段决定样本分布和天然可行性，无法仅靠 P1 引擎把未知输入补齐。

**选项：**A：逐场景显式模板与参数表，附来源/合成假设。B：事先登记的确定性 grammar
及参数化生成规则。两者均须提供完整字段和值；不是允许无限搜索的空授权。
A 容易复查和固定，但模板覆盖窄且可能人为强化预期竞争；B 覆盖可广，但更多自由度和
隐含拓扑偏差，增加物化/重放验证负担。相同输入必须对所有方法共享，不能按方法造输入。
有合法已知来源的 profile 可作为字段来源，但当前没有这种数据，不推荐任何具体数值。

**条件性建议：**先考虑 A 的可审计性，再由人工决定代表性和来源是否足够。
**须回答：**D01–D04、D06：选择哪类生成方式，并提供拓扑、代价、兼容、通信、扰动、
到达/deadline/窗口以及 H 可行性与负载分类的完整定义？
**关闭证据：**逐字段人工批准的规格+配置、来源链、实现身份与全部生成器/隔离/哈希
单测；未来 H 可行性结果另查，不能因规格批准就写为已实测通过。

## P2-B2 — 有限校准试验矩阵：UNRESOLVED

**事实与缺口：**E01 §§35–37 和 E02 允许校准 arrival intensity/deadline tightness/
burst/服务数/窗口；B2 焦点、baseline-only。E08 的 18 个主条件和十个 seed 只是约束，
未给 trial/config 列表、方法子集、顺序、预算、选择/平局和失败归属规则。

**选项：**A：人工枚举完整有限 trial 列表。B：批准全部有限轴和值后，按冻结的笛卡尔
展开和稳定键顺序编译完整列表。A 易审但易漏组合；B 可检查覆盖但会组合膨胀，需要先
计算和批准预算。没有轴值时两者都不能执行，不能把空列表当作成功试验。
方法可在现有 B1–B5 内选择：全部覆盖减少选择性报告风险但成本高；预注册子集可降低
成本但须解释遗漏影响。两者都不是现已选定的方案，当前 included_methods=null。

**建议：**用完整列表作为最终审批对象，不推荐未经证据支持的具体子集或 trial 数。
校准选择应依据压力、H 可行性和已批准的目标；不得按 candidate advantage 或看过
baseline 赢家后选择条件。选同一 seed 的多 trial 不增加独立 seed 样本量。
**须回答：**D05–D06：采用枚举还是有限轴展开，给出完整值/方法/顺序/预算及选择、平局、
无效/失败/不完整处理规则？
**关闭证据：**完整可检查的计划、人工批准和 hash；每条 seed 均来自 CALIBRATION；
编译器/完整性测试及未来全部 trial 的记录，包括不利结果。失败不准静默删除或默认重试。

## P2-B3 — 映射机会判据：UNRESOLVED

**事实与缺口：**E06:34–36 要求先登记“稳定 mapping opportunity”再使用诊断选择；
E07 §100 要求无稳定机会则停止假设。没有观察量、反事实、单位、稳定性、uncertainty
或三向判定的可执行定义。E07 §32 的手例明确不算科学证据。

**选项：**M1 同一可观测决策状态的机制诊断/合法备选映射；M2 现有基线的配对差异，
只作交叉证据。完整局限与规则见 mapping_criterion_options.md。
M1 接近稀缺资源机会机制但反事实调度需要预注册，可能受视窗/事件选择偏差影响；
M2 复用现有指标和方法但 ordering/mapping 混杂，不能单独证明 mapping 的因果作用。
无现有数值能推荐机会频率、effect size、稳定 seed 数或新 CI 阈值。

**条件性建议：**优先审查 M1 的可审计定义，M2 作为描述性交叉检查，而非把基线赢家
当作映射机会成立。该建议未获批准，M1/M2 均未计算。
**须回答：**D07–D08：选择何种观察/比较及单位；给出跨 seed/条件聚合、稳定性、
uncertainty 和 SUPPORTED/NOT_SUPPORTED/INCONCLUSIVE 的完整规则？
**关闭证据：**观察前批准的判据版本/全部参数/预期对照；已知正负/不确定/无效例的
实现验证；未来完整诊断原始链。任何 H/L 科学结论仍服从原协议，不能由机会判据替代。

## P2-B4 — 科学执行入口：DESIGNED（仅未批准文档）

**事实与缺口：**E09 没有 calibration 执行器，E11 只有 seed/既有 gate 守卫，
没有科学 run 恢复状态机。P2 pipeline 不曾调用，不能把静态 return 3 当作实际退出码。
缺少审定计划与 schema，导致无法唯一识别允许运行和何时安全复用结果。

**选项：**R1：保留现有 calibration 入口，另行实现受批准 manifest 驱动的 runner；
R2：另行实现薄 launcher，但必须调用相同守卫并使用唯一正式计划/状态机，不能形成旁路。
R1 有一个正式入口、审计路径较少，改入口需回归验证；R2 易隔离调度实现，但更易出现
重复来源和检查漂移。R1 是架构建议，不是本轮实现/调用授权。
恢复方面，建议只复用身份/哈希/验证完整匹配的已完成结果；不完整或失败停止并保留。
允许重试需事先明示条件/预算/新 attempt 身份，不能由“恢复”自动授予。

**须回答：**D09：选择正式 runner 架构，是否采纳完成产物精确复用、失败/不完整默认
停止、无自动重试的提案；并裁决 calibration 源状态的记录/洁净控制？
**关闭证据：**人工批准 runner 接口/状态机/恢复策略，D01–D08 的已批准计划，另行授权
实现，通过缺 seed、损坏文件、重复 identity、部分写入和非法重试故障测试。文档
DESIGNED 不等于 IMPLEMENTED，不解除 P2 前置 BLOCKED。

## P2-B5 — 科学产物 schema：DESIGNED（仅未批准文档）

**事实与缺口：**E10 的 origin 固定为手工 fixture；E07 §§41、90–92 及 E06 给出
科学身份/哈希/validity/完整性要求，但没有兼容适配方式或已验证科学 schema。
改标签不能证明新的科学生成来源。

**选项：**S1：带强制生成血缘的科学 envelope，保留 legacy P1 payload 与其标签原样；
S2：另立版本化科学 schema 家族与明确适配器，旧 P1 schema/字节/ID 保持。
S1 可能少改核心，但硬编码 fixture origin 的语义冲突尚待可行性审查，不能保证 envelope
足够；S2 来源语义清晰，但需要另行授权的接口扩展、P1 回归及新来源身份核验。
两者都必须证明科学输入来自已批准生成器与 calibration seed，拒绝 fixture 转样本。

**建议：**明确分开科学 namespace 与 P1，并强制 provenance/引用/语义检查；当前证据
不足以选定 S1 或 S2。schema 草案表达共同所需字段，不是选定了适配架构。
**须回答：**D10：批准哪种兼容路线、科学身份/规范化/链接规则及相应未来验证范围？
**关闭证据：**字段和语义批准、adapter 可行性审查、schema 正反例与血缘/哈希/标签
拒绝验证、旧 P0/P1 原件未变回归。仅 JSON parse 成功不能关闭本项。
