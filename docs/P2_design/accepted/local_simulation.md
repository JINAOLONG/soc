# Single-host research simulation scope

The user's later instruction “我不需要工程部署，只需要仿真结果就可以” supersedes
production-deployment prerequisites for this local simulation mode. Together
with “进入下一步实验” and the existing implementation authorization, it authorizes
implementation, correctness checks, registered CALIBRATION simulation and saved
results on the current cloud host. See `local_simulation_scope_001.json`.

This mode does not claim V3 production provenance/publication/recovery-contract
compliance. Original V3 definitions and previous failures remain unchanged.
The accepted synthetic model, seed identities, fixed finite trial roster,
controls, selection rules, scientific thresholds and later-stage locks remain.
No authority service, lease, fencing backend, permanent cloud volume or hardware
performance claim is needed or implied by a local virtual-time simulation.

Run `.venv/bin/python -B scripts/run_local_calibration.py --check-only` first,
then `.venv/bin/python -B scripts/run_local_calibration.py`. The execution path
is fixed to `results/calibration/local_001`; an existing directory is rejected,
so a second invocation cannot silently restart reserved or uncertain calls.
Local exclusive ownership and per-call exclusive reservation files prevent
duplicate admission through this entry. The old production entry remains
fail-closed and is not used for this expressly different execution mode.

Every parent is generated by the accepted exact arithmetic before controls are
derived. A separate validator independently computes the keyed draws, all
numeric cells, critical paths and control spacing from frozen decimal tables.
Control nodes, costs, links and deadlines inherit the parent exactly. All
1080 compressed inputs and exact sidecars are retained if the plan completes.

The fixed matrix's actual trial order is preserved, including controls before
the corresponding MAIN baseline calls. Every primary and its one registered
replay are reserved before invocation. Both physical traces are independently
checked; independently recomputed metrics must match and full compact Trace
bytes must replay exactly. A valid off-target configuration is retained and
ineligible; invalid inputs, illegal traces or replay mismatches stop the whole
plan without retries. No outcome-dependent new trials or parameter changes.

Trace stores every event/execution and every invocation's time/proposal.
Repeated static observations are omitted from the compact transport; immutable
input plus earlier starts/completions reconstruct the public views. Correctness
checks compare all45 fixture×baseline compact traces against full observations
and independently reconstruct invocation timing and proposals. Full physical
traces and deterministic replay are required for every scientific sample.

Each run records input/config/source/seed identities, Git commit/dirty scope,
host, exact campaign command, process identity, wall timestamps and validation.
Function calls are recorded as returned calls, never fabricated child exit0s.
The outer CLI's real exit is saved separately. Exact analysis occurs only if
fixed qualification succeeds across all18 conditions. An incomplete or failed
qualification cannot become a P2 PASS or authorize P3. No reserved partitions
are unlocked by this mode. Data are saved locally with hashes and published to
GitHub; survival of unpushed files after environment loss is not guaranteed.
